# agent-wiki 验收清单

该文档用于实际仓库上的人工验收。CI 验证的是 Python Helper 的确定性行为，**不等于已经验证 LLM 生成的 AGENTS.md 的语义正确性**。

## 1. 自动化验证

在 Windows、Linux 上运行：

~~~bash
python -m unittest discover -s tests -v
~~~

GitHub Actions 目前覆盖：

- Ubuntu + Python 3.9
- Ubuntu + Python 3.12
- Windows + Python 3.9
- Windows + Python 3.12

回归测试包含搜索文件内续扫、路径兼容、敏感文件排除和脱敏、Count 失效、Session/证据恢复、过长源码行、超大清单摘要和完整的 Helper CLI 链路。

## 2. 真实仓库验收（需人工执行）

建议选择三个规模不同且有代表性的目标：

| 类型 | 重点验证 |
|---|---|
| 小型 OSS C/C++ 组件 | 上游身份、导出接口、内部修改、证据引用、中文文档 |
| 中型 QNX / Android / Linux 组件 | 构建与部署证据、启动流程、IPC/RPC、模块边界、平台差异 |
| 大型多模块仓库 | 逐模块计划、输出上限、Session 恢复、缺失证据的标注、不重复扫描 |

每个目标执行：

1. 从目标仓库根目录触发 \`agents-md\` Skill，确认不会扫描整个父目录或相邻仓库。
2. 检查 Inventory 只返回精简元数据，且明确指出可能的截断与排除范围。
3. 查看 Scan Plan 是否围绕明确的问题选择文件，是否优先读取接口定义、构建清单和入口文件。
4. 用一条在同一文件内匹配超过 80 次的查询验证 \`next_offset\` + \`next_line_offset\` 续扫不会丢失行。
5. 检查 Evidence 是否具有有效路径、定位信息和 SHA-256，修改源文件后能否识别旧证据失效。
6. 在 Context Compaction 或新会话中执行 Resume，并核实下一任务与证据均可恢复。
7. 检查生成的 \`AGENTS.md\` **必须是简体中文**，技术标识符、宏、API 和源码路径保留原文。
8. 检查生成内容只包含项目架构、运行机制、接口契约、平台差异、真实约束、测试信息和维护边界。
9. 确认没有生成 \`NULL/nullptr\`、缩进、命名、Header Guard、版权头覆盖率等通用编码风格说明，也没有构建命令或 Git 工作流教程。
10. 检查不存在凭据、密钥及其他敏感内容，并验证原有人为维护的 AGENTS.md 不会被未经批准地覆盖。

## 3. 验收时必须保留的限制说明

- 文件清单超过上限，或搜索/计数跳过文件时，不得声称完整覆盖。
- 自动脱敏属于尽力而为，不是全面的密钥扫描。
- Python Helper 不解析 C/C++ 语义，Raw Count 不能作为接口或运行时行为的唯一证据。
- 如果新增或删除了计数范围内的文件，需要重新 Inventory；已扫描文件内容变化会使 Count 缓存失效。
- 文件哈希只能确认引用来源未变，不能自动证明 LLM 对代码的解释正确。

## 4. 通过标准

只有在自动化 CI 通过、真实仓库输出满足上述要求，并且现有文件刷新操作经过用户审核后，才能认为完整生成流程完成验收。

未做真实目标仓库测试时，应明确报告“Helper 已测试；LLM 文档生成质量尚未实测”，不得宣称端到端生成质量已经验证。
